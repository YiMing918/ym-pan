## 先选下载文件：部署包和源码包别下错

去仓库的 [Releases（发行版）页](https://github.com/YiMing918/ym-pan/releases/latest) 下载时，那里会躺着好几个文件，**下错了部署不了**，先对表：

| 文件 | 是什么 | 什么时候下它 |
|---|---|---|
| `ym-pan-deploy-日期.zip` | **部署包**：打包好的可部署文件（`index.html`、`_headers`、`functions/`），目录摆法就是上线要的样子 | 用方法四（后台上传）部署、手机救急、迁移到另一个 Cloudflare（简称 CF）账号时，下这个 |
| `SHA256SUMS.txt` | **校验文件**：里面是部署包的 SHA-256 指纹（一串由文件内容算出的编号，文件被改一个字节指纹就变） | 下完部署包顺手下它，对一下指纹确认包没损坏、没被调包 |
| `Source code (zip)` / `Source code (tar.gz)` | **源码包**：GitHub 自动把整个仓库打包的快照，混着测试、文档、脚本、截图 | 只适合看源码、或在电脑上用方法三（命令行）慢慢弄；**不要拿它当部署包直接传**——里面多余文件一堆，摆法也不对 |

## 新手先看这里：先备齐这些东西

没用过 GitHub、Cloudflare 也完全没关系，这一节先把要用的东西、人话概念和几把「钥匙」讲清，后面照着点就行。

### 先分清两个地方

部署这个站要打交道的就两个网站，先分清谁管什么，后面每一步说「去哪弄」你就不会迷路：

| 地方 | 它是干什么的 | 本项目在它这儿用到什么 |
|---|---|---|
| **GitHub**（github.com） | **放代码的地方**。代码存在「仓库」里（一个仓库 = 一个项目的文件夹）；**Actions**（自动任务）是仓库里干活的机器人，你不用守着，它按规矩自动部署、自动巡检；**Releases**（发行版）是把打包好的文件摆出来给人下载的货架；**Secrets**（机密）是仓库里存钥匙的保险柜，只写不读、任何人（包括你自己）填完都再也看不到原文 | 本仓库的代码就放在这儿；机器人 `deploy` 负责把代码推上 CF 部署，机器人 `watchdog`（看门狗）每天巡检；部署包 zip 摆在 Releases 里；部署用的 CF 令牌就锁在 Secrets 里 |
| **Cloudflare**（dash.cloudflare.com，简称 CF） | **让项目跑起来的地方**。网站真正运行、有人访问时应答的，都是它。左侧菜单里本项目只用到两处：**Workers 和 Pages**（网站本体住这里，设置、绑定、环境变量都在项目页里改）、**存储和数据库 → KV**（KV 是一种最简单的云端记事本，按「名字 → 内容」存东西） | 网站跑在 **Pages**（托管网页 + 后端函数的服务）上；站长保险箱里的各家凭证、口令哈希就存在 **KV** 里——凭证是在**站内页面**的保险箱卡里填的，页面把它们写进你 CF 账号的 KV，CF 后台不用你手动去存 |

**两边怎么配合**：你在 GitHub 这边改代码、点推送 → GitHub 的机器人拿着你锁在 Secrets 里的 CF 令牌，去 Cloudflare 那边把新代码换上 → 访客打开站点，访问的是 CF 上跑着的那一份。GitHub 是「仓库 + 施工队」，Cloudflare 是「房子本体」。

### 动手前备齐这四样

1. **一个 GitHub 账号**：去 github.com 注册，免费。没有它，方法一、二用不了（方法四可以绕开，但不推荐）。
2. **一个 Cloudflare 账号**：去 dash.cloudflare.com 注册，免费。本站跑在它的免费额度里，不绑卡也能用本文全部功能。
3. **（可选）一个自己的域名**：没有也行——CF 会免费给你一个 `你的项目.pages.dev` 地址，能用；有域名可以绑上显得正规，域名要先把解析托管到 CF（在 CF 控制台点「添加站点」按提示去域名商那改一次名称服务器，控制台会一步步指你）。
4. **一部手机或电脑**：九家网盘扫码登录要用手机 App；部署本身手机也能做（方法四），电脑更顺手。

### 先认识这几把「钥匙」（每把都说清：是什么、去哪拿、填到哪、干什么、怎么保管）

部署和使用中会遇到好几样长得像密码的东西，新手最容易在这里晕。一把一把说清：

**① CF API 令牌（CLOUDFLARE_API_TOKEN）**
- **是什么**：一串字符，相当于你 CF 账号的一把「限权钥匙」——只许干「改 Pages 部署」这一类事，丢了也不至于丢整个账号。
- **去哪建**：CF 控制台右上角头像 → **我的个人资料** → **API 令牌** → **创建令牌** → **创建自定义令牌**，权限只加一条「账户 → Cloudflare Pages → 编辑」，账户资源选你的账号，点创建。**做到这里你应该看到**：页面显示一串令牌字符，并提示只显示这一次。
- **填到哪**：你 GitHub 仓库的 **Settings（设置）→ Secrets and variables → Actions（自动任务）→ New repository secret（新建机密）**，名字填 `CLOUDFLARE_API_TOKEN`、值粘贴这串令牌，点 Add secret（添加）。
- **干什么用**：GitHub 的部署机器人每次替你部署时，拿它向 CF 证明「我是主人派来的」。
- **要不要保存**：令牌原文**只显示一次**，当场复制走——除了填进 Secrets，再在自己的密码管理器（手机备忘录也行，但别发给任何人）里存一份。**丢了怎么办**：没法找回原文， CF 控制台 → API 令牌里把旧的删掉、照上面重建一把新的、把 Secrets 里的值换成新令牌即可，不影响站点数据。**以后啥情况再用**：换部署账号、怀疑令牌泄露、或者 Secrets 被清空时，才需要再动它。

**② CF 账号 ID（CLOUDFLARE_ACCOUNT_ID）**
- **是什么**：你 CF 账号的编号，一串数字字母。它**不是秘密**，就是个门牌号。
- **去哪拿**：CF 控制台 → **Workers 和 Pages** 概览页右侧「账户 ID」那一行，点一下复制。
- **填到哪**：和令牌同一个地方（仓库 Secrets），名字填 `CLOUDFLARE_ACCOUNT_ID`。
- **干什么用**：告诉部署机器人「把代码部署到哪个 CF 账号」。
- **要不要保存**：不用特意存，忘了随时回 CF 控制台看。

**③ 巡检口令（PATROL_KEY）**
- **是什么**：一串**你自己想的**长字符，相当于站长专用的「内部暗号」，不是任何平台发给你的。
- **去哪设**：CF 控制台 → 你的 Pages 项目 → **设置 → 环境变量** → 生产环境「添加变量」，名字填 `PATROL_KEY`、值填你想好的长随机字符（建议 20 位以上、别和任何密码重复），勾选「加密」，保存后**重新部署一次**才生效。
- **干什么用**：三件事——①给保险箱**开设置窗口**（防止陌生人抢先给你的站设站长口令）；②调用巡检接口 `/api/patrol` 做带真凭证的自检；③重绑夸克巡检凭证时验明正身。
- **要不要保存**：**必须自己记牢**，存进密码管理器。它在 CF 里只显示「已加密」看不到原文。**丢了怎么办**：回到 Pages 项目 → 设置 → 环境变量，把 `PATROL_KEY` 的值改成一串新的、保存并重新部署即可（改它不会动保险箱和凭证）；但改完之后，之前靠旧口令绑的巡检调用（如站外巡检脚本）要同步换新值。**以后啥情况再用**：每次开保险箱设置窗口、手动巡检、重绑扫码凭证时都要用它。

**④ 站长口令（保险箱口令）**
- **是什么**：你在**站内页面上自己设的**一串口令，是保险箱的门锁。和上面巡检口令是两回事：巡检口令管「后台动作」，站长口令管「打开保险箱」。
- **去哪设**：部署完打开你的站点 → 拉到「② 我的凭证 → 站长保险箱」卡 → 按下面[认领站长](#认领站长第一次打开先设口令)一节的步骤设。服务器只存它的哈希（指纹），**任何人——包括帮你部署的人——都看不到原文**。
- **干什么用**：解锁保险箱；解锁后在任何设备上解析都自动带保险箱里存的凭证，不用每台设备重填。
- **要不要保存**：**自己记牢**。**丢了怎么办**：先用恢复码（见下）在站内重置；恢复码也丢了，还有终极办法——登录你自己的 CF 后台，把 KV 里几个键删掉重设（步骤在 MAINTENANCE.md，新手别慌，那是最后手段，数据是各家凭证、重存即可）。**以后啥情况再用**：换设备、换浏览器、保险箱自动锁定时，输它解锁。

**⑤ 恢复码**
- **是什么**：设站长口令成功那一刻，页面签发给你的一串码，等于保险箱的「备用钥匙」。
- **去哪拿**：只在设口令/重置口令成功后**显示一次**，页面会专门提示你抄存。**做到这里你应该看到**：一串恢复码和「只显示一次」的提醒——立刻抄进手机备忘录或密码管理器，再继续操作。
- **干什么用**：忘站长口令时，在保险箱卡点「忘口令？用恢复码重置」，输它直接重设新口令。
- **要不要保存**：**必须存**。丢了、且口令也忘了，就只能走上面的 CF 后台终极重置。**以后啥情况再用**：只有忘口令重置时用，平时用不上，也别给任何人看。

**⑥ 各家网盘的凭证（BDUSS、Cookie、Authorization 等）**
- **是什么**：你登录各家网盘**网页版**之后，浏览器手里握着的「已登录凭据」——本质上是网盘认你已登录的票据。具体每家要哪个、去哪拿，见[凭证从哪拿](#凭证从哪拿)一节的对照表；九家还能直接扫码自动拿到（见使用方法第一步）。
- **填到哪**：站内「② 我的凭证」对应输入框，点「保存凭证」；站长解锁保险箱后保存会顺带同步进保险箱（也就是存进你 CF 的 KV）。
- **干什么用**：本站函数替你调各家官方接口解析分享时，要拿它证明「这是账号主人本人的请求」——没有它，多数盘只能看目录、拿不到下载直链。
- **要不要保存**：访客填的只存在**你自己浏览器的本地存储**里，关掉页面不丢、换设备要重填；站长存进保险箱的在自己 KV 里，换设备输口令就行。凭证**会过期**（各家几天到几周不等），过期了重新登录拿一次、或重新扫码即可，不是出大事了。**千万别把凭证发给任何人或贴到公开地方**——拿到它的人能以你的身份操作网盘。

## 功能全清单：都有什么、都能干什么

页面从上到下五块，后台还有一整套自动运维。逐项说清：

### ① 解析分享（网盘直链）
- **选盘解析**：点选网盘 → 粘贴分享链接（**整段分享文字直接粘**，链接和提取码自动识别）→ 出文件列表。
- **文件夹导航**：分享里有文件夹可逐层打开，面包屑式返回。
- **单文件取链**：每个文件一个「取链」按钮，出直链 + 专用请求头 + 有效期提示。
- **批量取链**：勾选多个文件一次全取，汇总成一张清单。
- **直链三件套**：每个结果都能 ①复制直链 ②复制「链接+请求头」（给 1DM+ 这类要填请求头的下载器）③复制现成的 **aria2 命令**；批量结果还能**导出 aria2 格式 .txt** 喂给 aria2/Motrix。
- **路线标注**：结果旁标明实际走通的路线（哪条接口、哪个镜像域名），坏没坏、走的哪条，一眼可见。
- **多路线互备**：123 双接口路线、蓝奏多个官方域名同码轮试、夸克/UC 双网关——一条路线坏了自动换另一条。

### ② 我的凭证
- **11 家凭证集中一表**：每家一个输入框，带「从哪拿」的占位提示；只存**本机浏览器**，随解析请求发给本站函数、用完即弃、不落盘。
- **自动回写**：夸克/UC 的 Cookie 每次响应都会轮换新值（`__puus`），本站自动把新 Cookie 回写到你本地凭证，不用手动追着换。
- **扫码登录（百度/阿里/夸克/UC/移动/天翼/光鸭/123/迅雷 9 家）+ 账号密码登录（仅小飞机 1 家）**：没有电脑、不会挖 Cookie 也没关系——凭证卡里点「扫码登录」，用对应 App 扫码确认即可，凭证自动填进表格（站长解锁保险箱时自动同步进保险箱）；阿里、迅雷扫码会连刷新令牌一起存，解析时自动换新令牌、基本不用再扫；123 扫码与 123 官网登录页同款通道（123 App 扫一扫或微信扫均可；App 扫不需绑微信，站长 2026-11-10 已真扫成功；微信扫需账号绑过微信），迅雷扫码是其官网登录页同款的 OAuth2 设备码流程（扒官方账号 SDK 源码复刻，用手机迅雷 App 扫）。小飞机官方没扫码通道但其接口支持账密，填账号密码即可登录，**密码只透传给官方换令牌、本站不保存**。123 账密登录已删除：官方按登录 IP 做风控，本站请求从境外服务器发出恒被判「境外登录风险」（2026-11-10 真账号实测），走不通的功能不留；手填 Authorization 照旧可用（两种方法并存互备：扫码坏了用手填，手填找不到用扫码）。协议逐项对照久经验证的开源实现与官方前端代码（百度 passport、夸克/UC CAS、阿里 passport mini_login、移动 orchestration 签名流、天翼 logbox、光鸭设备码流、123 官网 qr-code 接口、迅雷账号 SDK 设备码流）；看门狗每天逐家探活 9 家扫码通道。
- **缺凭证提示**：哪家没填、解析时必须要哪项（如阿里取链必须 Authorization），页面会明确点名提示，不给含糊报错。
- **夸克巡检凭证（扫码绑定）**：站长专用——手机夸克 App 扫码一次，Cookie 存进自己 Cloudflare 的 KV，供每日真巡检使用；二维码过期自动换新。
- **站长保险箱**：站长自设一个口令（只存哈希，站长自己在站内设、不经任何人手），把各家凭证存进**自己 Cloudflare 账号的云存储**一次；之后在**任何设备**上输一次口令，解析自动带保险箱里的凭证免填——用的还是站长自己的账号。细节：
  - **同步可见**：保险箱里已存哪几家，页面明文列出；每个凭证输入框旁标「保险箱已同步 ✓」；换设备输口令就能看到自己到底登了哪几家（凭证原文永不下发回浏览器，只显示已存状态）。
  - **保存即同步**：解锁状态下点「保存凭证」，自动顺带同步进保险箱；先登两家、以后陆续登别家，集合在云端自动累积。
  - **忘口令三层恢复**（第 ①③ 层完全自助）：①设口令时签发的**恢复码**（只显示一次，自己存好）站内直接重置；②请人用巡检口令开 30 分钟设置窗口；③终极路：登录自己的 Cloudflare 后台删掉 KV 里 `owner_hash`、`owner_recovery_hash` 两个键、再把 `vault_` 开头的键全删，站点恢复未认领状态（步骤在 MAINTENANCE.md）。
  - **防抢设**：首次设置窗口平时关闭，须巡检口令开启 30 分钟，防止陌生人抢先给你的站设口令。

## 使用方法（一步一步）

### 第一步：填凭证（每家只填一次）
1. **九家可以直接扫码**：在凭证卡「扫码登录」区点对应按钮，用手机 App 扫码确认，凭证自动填好，跳过后面所有步骤（百度 / 阿里 / 夸克 / UC / 移动 / 天翼 / 光鸭 / 123 / 迅雷；其中 123 用 App 扫一扫或微信扫均可，App 扫不需绑微信（站长已真扫成功），没绑微信的用 App 扫）；**小飞机**在同区填账号密码登录（密码不保存、只换令牌）。哪家都不用再去浏览器里挖 Cookie；万一哪天某家扫码通道被官方改版打断，凭证表手填的老路也还在（方法见下方[凭证从哪拿](#凭证从哪拿)）。
2. 打开本站「② 我的凭证」，粘进对应输入框，点「保存凭证」。（站长另有保险箱，见第六步。）
3. 不用的盘不用填；哪家缺凭证，解析时页面会点名提醒。

### 第二步：解析网盘分享
1. 在「① 解析分享」点选网盘（没选对也能靠链接域名纠正一部分，但建议先选对）。
2. 把分享链接粘进输入框——**整段分享文字**（如「链接：https://… 提取码：abcd」）直接整段粘，提取码框会自动填好。
3. 点「解析」→ 出现文件列表；有文件夹点「打开」逐层进。
4. 单个文件点「取链」；多个文件勾选后点「批量取链（勾选）」。

### 第三步：拿直链去下载
- **1DM+ / ADM（安卓）**：复制「链接+请求头」那一份，在下载器新建任务时把请求头粘进高级设置；或直接复制直链、再按结果里列出的请求头逐项填（User-Agent、Cookie、Referer 缺一不可的那几家页面会写明）。
- **aria2 / Motrix**：复制现成的 **aria2 命令**到终端执行；批量时用「导出 aria2.txt」，aria2c 加 `-i aria2.txt` 一次全下。
- **IDM（电脑）**：复制直链新建任务，在任务属性里补结果中列出的请求头。
- 直链都有时效（几十分钟到数小时，百度约 8 小时），过期回本站重新取一次即可。

### 第四步：视频解析
1. 在短视频 App 里点「分享 → 复制链接」。
2. 粘进「④ 视频解析」输入框（整段文案也行），点「解析」。
3. 按清晰度点「打开直链」或「复制」，同样可交给下载器；微博的链记得带结果里标注的 Referer。

### 第五步：某家坏了先自检
1. 点「③ 接口自检 → 开始自检」，看哪家不通。
2. 接口通、解析失败：多半是该家改了口径，等本站跟随上游更新（或提 Issue（问题帖）附上报错原文）。
3. 接口不通：对方维护或临时封 IP，过段时间再试。

### 第六步：站长保险箱（站长本人专用，一次设置长期省事）
1. 首次设置需要先开设置窗口（窗口平时关闭防抢设）：用你部署时自设的巡检口令调 `POST /api/owner {"action":"open-setup"}` 并带 `x-patrol-key` 请求头，或按 MAINTENANCE.md 的方法处理。
2. 30 分钟内回页面「② → 站长保险箱」，自己想一个口令填入并点「设置口令」——页面会显示一串**恢复码，只显示这一次，立刻抄存到手机备忘录**。
3. 把各家凭证填进上面的表格，点「保存凭证」（已解锁时自动同步进保险箱），或点保险箱里「把上面填好的凭证存进保险箱」。
4. 以后换手机/换浏览器：打开站 → 输口令解锁 → 解析自动免填；保险箱卡片会列出已存哪几家。
5. 忘口令：点「忘口令？用恢复码重置」输恢复码即可；恢复码也丢了，看 MAINTENANCE.md 的 Cloudflare 后台终极重置法。

### 第七步：扫码绑定夸克巡检（站长专用，可选但推荐）
1. 在「②」下方「夸克巡检凭证（扫码绑定）」点生成二维码。
2. 手机打开**夸克网盘 App** 扫码并确认登录（码过期会自动换新，页面有倒计时；扫完要立刻在 App 里确认）。
3. 绑定后巡检接口 `/api/patrol` 即可用该凭证做真解析自检；日常由看门狗/巡检脚本带巡检口令调用，本人不用管。

## 原理：每家怎么解析的

本站函数（`functions/api/parse.js`、`video.js`）在服务端替你走各家网页版/官方接口的标准流程，浏览器不直连网盘（避开跨域），凭证只出现在你与本站之间的请求里：

- **百度**：GET 分享页取 `sign/timestamp/shareid`（顺手拿 `PANPSC`）→ POST `share/verify` 验提取码得 `randsk` → `share/list` 列目录 → `api/sharedownload` 取 `dlink`。下载端须带 `netdisk` UA 与 BDUSS。
- **阿里**：`get_share_token`（匿名+提取码）→ `list_by_share` → `get_share_link_download_url`；实测匿名只能列目录，取直链必须带自己的 Authorization（未填时页面会明确提示）。
- **夸克 / UC**：`sharepage/token` 拿 `stoken` → `sharepage/detail` 列目录 → 小文件 `file/download` 直取；大文件先 `sharepage/save` 转存进你自己盘根目录再取链（转存物可事后删）。响应里的新 Cookie（`__puus` 轮换）会回吐给页面自动更新本地凭证。
- **蓝奏**：分享页 → iframe 子页提取 `wp_sign`/`ajaxdata` 与主页数字 `fid` → POST 现行端点 `apifile.woozooo.com/ajaxfile.php`（备 `apifile.lanzouw.com`、老 `ajaxm.php`）得 `dom + url` 拼直链；域名失效自动换官方等价域名同码重试。
- **移动**：`share-kd-njs.yun.139.com` 网关：请求体 AES-128-CBC 加密（IV 前置）+ 设备头 → `getOutLinkGeneral` 自动补提取码 → 列目录合并文件夹/文件两类清单 → 取链 `dlFromOutLinkV3`（需登录态 + mcloud-sign 签名头）。
- **天翼**：`cloud.189.cn` 签名口径：`checkAccessCode`（有访问码时）→ 签名 `getShareInfoByCodeV2`（MD5 字典序拼参 + Sign-Type/Timestamp/AppKey 头）→ `listShareDir` 分页（大整数 id 按字符串防精度丢失）→ `getFileDownloadUrl` 取链（多半需 Cookie）。
- **小飞机**：`recommend/list` 列目录（AES 签名时间戳）→ `/ws/file/redirect` 取跳转直链（downloadId/auth 双 AES）；旧 `/ws/share/list` 已废弃、仅作兜底。
- **123**：列目录走现行匿名端点 `yun.123pan.cn/b/api/share/get`（Dart UA、无 token、无提取码时整参省略 SharePwd、Page 翻页）；取链 `www.123865.com/b/api/share/download/info` + CRC32 客户端签名，先匿名试、失败再带 Authorization 重试，DownloadURL 解 Base64 包装并跟跳转。
- **夸克/UC**：取链三路线——游客免转存（小文件）→ 登录直取 → 转存（轮询任务到 status==2、用新 fid、取链只带 fids）；`file/download` 必须带官方 PC 客户端 UA，网页 UA 会被当游客档、大文件恒回 23018（2026-11-11 实证）；`__dt/__t` 每次请求新鲜生成。
- **迅雷**：列目录游客段用安卓身份自算 captcha 签名（盐表公开、设备号持久化），根目录 `/drive/v1/share`、子目录 `/drive/v1/share/detail?parent_id=`；取链需登录：同号直查、异号 `settings`+`share/restore` 转存后 `files/{id}?usage=CONSUME` 取链，压缩包先改名再取；存了抓包 sign 时优先用存量 sign 换令牌，上游回验证页时把链接透传给用户本人完成。
- **光鸭**：`get_share_access_token` 拿匿名分享令牌列目录/取链，令牌不够用时以登录令牌（gyToken）兜底、gyRefresh 自动续期。
- **视频**：各平台分享页/接口取无水印地址——抖音四级链（分享页 → ttwid 解锁 → 老接口 → Web detail）、快手 H5 页双 JSON 通道、微博游客两段式 + 组件换 mid + `playback_list` 多档、小红书笔记页原画字段（短链多策略解链 + 双域名笔记页互备；rednote.com 海外域名已认；CF 出口风控墙见平台表）、AcFun `ksPlayJson` 多档、即梦 `get_item_info` 现行接口、B站 WBI 签名 + buvid + bili_ticket（机房出口仍常被 412，如实标注）、TikTok 网页 SSR + App 接口 + tikwm 第三方兜底三路线。

## 部署总览与部署方式对比

部署就是「把代码弄到 Cloudflare 上跑起来」。一共四种方式，**先看对比表选一种**，再翻到对应小节照着做。四种方式部署出来的站点完全一样，区别只在「怎么把代码送上去、以后更新方不方便」。不管选哪种，部署完都要接着做[部署后必做配置](#部署后必做配置)和[认领站长](#认领站长第一次打开先设口令)，才算齐活。

| 对比项 | 方法一：CF 后台连接 Git | 方法二：GitHub Actions 自动部署 | 方法三：本地命令行 wrangler | 方法四：CF 后台直接上传 |
|---|---|---|---|---|
| 需要什么设备 | 手机或电脑，有浏览器就行 | 手机或电脑，有浏览器就行 | **必须有电脑**，还要装 Node.js 和命令行工具 | 手机或电脑，有浏览器就行 |
| 上手难度 | ★☆☆☆ 最简单，全程点鼠标 | ★★☆☆ 多配两把「钥匙」（令牌+账号 ID） | ★★★★ 要敲命令，新手最容易在这卡住 | ★☆☆☆ 最简单，拖文件就行 |
| 第一次大约耗时 | 约 10 分钟 | 约 20 分钟（多花在建令牌、填机密上） | 约 20 分钟（不含装环境；装环境另算） | 约 5 分钟 |
| 日常更新方不方便 | 方便：推送代码自动上线 | 最方便：推送自动上线，**还带自检门** | 不方便：每次更新要自己再敲一遍命令 | 最不方便：每次更新都要重新下载、重新上传整包 |
| 出错了好不好排查 | 一般：要去 CF 后台看部署记录 | **最好**：GitHub Actions 里每一步红绿灯分明，哪步红了点开看日志 | 好：报错直接打在你自己的终端窗口里 | 差：上传失败只给笼统提示，难定位 |
| 自动巡检（看门狗）能用吗 | 能（看门狗是另一个独立机器人） | 能，且与部署联动最好 | 能 | 能，但它自愈后要触发部署，你这条路触发不了（见方法四劣势） |
| 适合谁 | **大多数新手**、想最快拥有自己站的人 | 想要最稳、打算长期用、怕坏代码上线的人（**作者本人用的就是这种**） | 有电脑、会一点命令行、想本地调试的人 | 只想临时试一下、或手机救急/迁移时 |

**一句话选法**：纯新手、图省事 → 方法一；打算长期正经用 → 方法二；只有手机、想先试试水 → 方法四先跑起来，以后随时能换成方法一/二（站点数据都在 KV 里，换部署方式不丢）。

## 部署方法（全部四种，一步一步）

开始之前先把代码弄到你自己手里：打开本仓库页面 → 点右上角 **Fork**（复刻）按钮 → 选你的 GitHub 账号，几秒后你账号下就有一份一模一样的仓库（方法三、四可以跳过这步，方法三用克隆、方法四用下载）。下面四种方法任选其一。

### 方法一：Cloudflare 后台连接 Git（最简单）

**优势**
- 全程在网页里点鼠标，不用装任何软件、不用敲命令，手机上也能完成。
- 以后在 GitHub 上改了代码（或点 Sync fork 同步了上游更新），CF 会自动重新部署，不用你再操作。
- 部署记录、绑定、域名全在 CF 一个后台里管，找东西方便。

**劣势**
- 没有「自检门」：代码推上去就直接部署，万一哪次更新本身有问题，坏版本会直接上线（方法二有冒烟测试拦一道）。
- 部署失败时 CF 给的提示比较笼统，新手定位问题不如方法二看 Actions 日志直观。
- Pages 项目是在 CF 引导下建的，项目名等设置要自己留意，别和已有项目重名。

****
- 你的 GitHub 账号里 Fork 好的本仓库（见本节开头）。
- 你的 CF 账号。
- 不需要任何令牌——这条路是 CF 直接获得你 GitHub 的授权来拉代码。

****

<details>
<summary>点开看详细步骤</summary>

1. 打开 [Cloudflare 控制台](https://dash.cloudflare.com/) 并登录 → 左侧菜单点 **Workers 和 Pages** → 点 **创建应用程序**（Create application）→ 选 **Pages** 页签 → 点 **连接到 Git**（Connect to Git）。
2. 第一次用会让你授权 Cloudflare 访问 GitHub：点授权按钮跳到 GitHub，选你的账号、允许访问你 Fork 的那个仓库，确认。**做到这里你应该看到**：回到 CF 后，仓库列表里能看到你 Fork 的 `ym-pan` 仓库。
3. 点选该仓库 → 点 **开始设置**（Begin setup），来到构建设置页：
- **项目名称**：填 `ym-pan`（这决定你的免费地址是 `ym-pan.pages.dev`；想换名字也行，记住它后面绑域名要用）。
- **生产分支**：`main`。
- **框架预设**（Framework preset）：选 **无 / None**。
- **构建命令**（Build command）：**留空，什么都不填**。
- **构建输出目录**（Build output directory）：填 `/`（一个斜杠，表示仓库根目录就是成品）。
4. 点 **保存并部署**（Save and Deploy），等大约 1 分钟。**做到这里你应该看到**：部署状态变绿，出现一个 `https://ym-pan.pages.dev`（或你项目名对应的）地址，点开能看到本站的页面——五块卡片（解析分享/我的凭证/接口自检/视频解析/说明卡）都在。
5. 先别关页面，接着做[部署后必做配置](#部署后必做配置)（绑 KV + 设巡检口令），不然保险箱和巡检用不了。

</details>

****
- 打开你的 `pages.dev` 地址，页面完整出现、点「③ 接口自检 → 开始自检」， 11 家接口多数显示通（个别家临时维护变红不算部署问题）。
- 随便找一个真实分享链接粘进「① 解析分享」点解析，能列出文件列表 = 解析链路通。
- 做完[部署后必做配置](#部署后必做配置)第 4 步的完整验收清单，才算部署完成。

****
- **构建/部署变红失败**：先回头查第 3 步——框架预设是不是没选「无」、构建命令是不是手贱填了东西、输出目录是不是不是 `/`。这三处错一处就可能红。
- **页面打开是空白或 404**：多半是项目根目录不对；确认仓库根目录下直接躺着 `index.html`（Fork 的原样就是对的，别自己套一层文件夹）。
- **保险箱提示「KV 未绑定」**：不是部署失败，是还没做[部署后必做配置](#部署后必做配置)第 1 件（绑 KV），补上并重新部署一次即可。

### 方法二：GitHub Actions 自动部署（带自检门，与作者同款）

**优势**
- **有自检门**：仓库自带的 `deploy` 机器人每次部署前先跑一遍冒烟测试（`tests/smoke.mjs`，一套自动检查后端接口对不对的脚本），**测试不过就不许部署**，线上继续跑旧版——坏代码上不了线，这是四种方式里最稳的一条。
- 排查最方便：GitHub 仓库的 **Actions**（自动任务）页里，每一步绿勾/红叉一目了然，红了点开就是日志。
- 和看门狗联动：看门狗自愈改完配置后，靠这条流水线自动重新上线。

**劣势**
- 第一次配置步骤最多：要建 CF 令牌、找账号 ID、填两个 Secrets（机密），大约多花 10 分钟。
- 依赖 GitHub Actions 服务本身，它偶尔抽风时部署会排队或失败，重跑一次即可。
- 没配令牌时部署步会自动跳过——新手容易误以为「推了代码就部署了」，其实机器人根本没钥匙（见常见问题）。

****
- 你 GitHub 账号里 Fork 好的本仓库，且仓库的 Actions 功能已启用（Fork 后去仓库 **Actions** 页，若提示启用就点启用）。
- **CF API 令牌**一把、**CF 账号 ID**一个（这两样是什么、去哪拿、怎么保管，见[新手先看这里](#新手先看这里先备齐这些东西)的「钥匙」节，先照那节建好再回来）。
- CF 那边**先手动建好一个 Pages 项目的占位**不用——机器人会用 wrangler（CF 官方命令行工具）直接部署到名为 `ym-pan` 的 Pages 项目，项目不存在时它会自动创建。

****

- Actions 里最近一次 deploy 运行全绿；`pages.dev` 地址打开页面完整；「③ 接口自检」能跑。

****
- **推了代码，Actions 里 deploy 根本没跑**：先看仓库 Actions 功能是不是没启用（Fork 的仓库默认可能关着，去 Actions 页点启用）；再看推送是不是推到了 `main` 分支（其他分支不触发）。
- **冒烟测试绿了、部署步直接跳过（灰色 skipped）**：这是**没配令牌**的表现——机器人找不到 `CLOUDFLARE_API_TOKEN` 就自动跳过部署。回第 2 步把两个 Secrets 补齐，再手动 Run 一次。
- **部署步红了、日志说认证失败（Authentication error）**：令牌拷错、令牌被删、或令牌权限没勾「Cloudflare Pages → 编辑」。照「钥匙」节重建一把、更新 Secrets 里的值，再重跑。
- **冒烟测试红了**：别慌，线上没受影响。点开红步看日志末尾的报错；如果是你刚改的代码引起的，改回去再推；如果没改代码也红，可能是上游接口临时变动，等看门狗巡检结论或提 Issue（问题帖）。

### 方法三：本地命令行 wrangler（有电脑、会一点命令行）

**优势**
- 不依赖 GitHub：不用 Fork、不用配 Secrets，代码在你电脑上、部署命令也在你电脑上跑。
- 出错信息直接打在终端里，哪一步、什么原因看得最清楚；还能在本地先跑起来调试。
- 部署内容完全由你掌控：命令里打包哪几个文件一清二楚。

**劣势**
- 门槛最高：要先装 Node.js 和 wrangler，还要会复制粘贴命令、看懂终端提示。
- **没有自动更新**：每次改代码或同步上游，都要自己重新执行一遍打包 + 部署命令。
- 没有自检门兜底（除非你自己先跑一遍 `node tests/smoke.mjs`——推荐这么做，见步骤）。

****
- 一台电脑（Windows / Mac / Linux 都行），装好 **Node.js 18 以上**（去 nodejs.org 下安装包一路下一步；装完打开终端输入 `node -v` 能出版本号就算好）。
- 本仓库的代码一份：在仓库页点 **Code → Download ZIP** 下载解压，或用 git 克隆。
- 你的 CF 账号（部署时 wrangler 会弹浏览器让你登录授权，不用事先建令牌）。

****

<details>
<summary>点开看详细步骤</summary>

```bash
npm install -g wrangler # 装 CF 官方命令行工具（只需装一次）
wrangler login # 浏览器会弹出来，点允许，授权你的 CF 账号
# 进入你解压/克隆出的 ym-pan 文件夹后再执行下面几行：
node tests/smoke.mjs # 先自检一遍：全绿再部署（这就是方法二那道自检门，手动版）
mkdir -p dist/functions
cp index.html _headers dist/ && cp -r functions/. dist/functions/
npx wrangler@3 pages deploy dist --project-name ym-pan --branch main
```

Windows 电脑没有 `cp` 命令的，用文件管理器手动做同样的事：新建 `dist` 文件夹，把 `index.html`、`_headers` 拷进去，再建 `dist/functions` 把 `functions` 文件夹里的文件全拷进去，然后只执行最后一行部署命令。

**做到这里你应该看到**：终端最后打印出 `https://ym-pan.pages.dev` 之类的部署成功地址。之后每次更新：重新拷文件覆盖 `dist`、再跑最后一行即可。

</details>

****
- 打开终端给的地址，页面完整；「③ 接口自检」能跑；再做[部署后必做配置](#部署后必做配置)并走完验收清单。
- 注意：KV 绑定、环境变量是在 **CF 后台的 Pages 项目**里配的（见必做配置），跟你用什么方式部署无关，命令行部署完一样要去后台补。

****
- **`wrangler login` 没弹浏览器或授权失败**：检查终端网络；公司/校园网拦授权页时换个网络重试。也可以改用令牌方式：按「钥匙」节建令牌，在终端设环境变量 `CLOUDFLARE_API_TOKEN` 后再部署。
- **部署成功但打开是旧页面**：多半是浏览器缓存，强制刷新（Ctrl+F5）；或确认你拷进 `dist` 的是新文件不是旧文件。
- **`node tests/smoke.mjs` 红了还硬部署**：别。红说明后端契约对不上，部署上去也是坏站，先修或等更新。

### 方法四：Cloudflare 后台直接上传（不用 Git）

**优势**
- 最快试水：下个 zip、拖进网页、几分钟就能打开自己的站，不用注册 GitHub、不用装软件。
- 迁移救急好用：换 CF 账号时，把部署包传到新账号的 Pages 里就能重新跑起来。

**劣势**
- **永远不会自动更新**：上游出了新版、你改了代码，都必须自己重新下载整包、重新上传一遍，漏传一个文件就可能半残。
- 看门狗自愈后需要触发部署才能上线，这条路没有自动部署通道，自愈改的代码躺在仓库里上不了线（除非你手动重传）。
- 出错提示笼统，传漏文件时往往只表现为「某个功能坏了」，难排查。
- **千万别下错包**：要下 Releases 里的**部署包**（见[先选下载文件](#先选下载文件部署包和源码包别下错)），拿源码包来传会把测试、文档都传上去，结构也不对。

****
- 发行版里的部署包 zip：`ym-pan-deploy-日期.zip`（在 [Releases 页](https://github.com/YiMing918/ym-pan/releases/latest)下，顺手下 `SHA256SUMS.txt` 对一下指纹）。
- 你的 CF 账号。不需要 GitHub 账号、不需要令牌。

****

<details>
<summary>点开看详细步骤</summary>

1. 把部署包 zip **解压**到一个文件夹。**做到这里你应该看到**：文件夹打开第一层就直接是 `index.html`、`_headers` 和 `functions` 文件夹——如果解压出来先是一层同名文件夹，进去把里面那层的内容当准（上传时要保证 `index.html` 在上传内容的最外层）。
2. 打开 CF 控制台 → **Workers 和 Pages** → **创建** → **Pages** → **上传资产**（Upload assets）。
3. 项目名填 `ym-pan`，把解压出的**全部内容**拖进上传区（或点选择把文件和 `functions` 文件夹一起选上），点部署。
4. 等它传完变绿，**做到这里你应该看到**：你的 `ym-pan.pages.dev` 地址，打开是完整页面。
5. 接着做[部署后必做配置](#部署后必做配置)——绑 KV、环境变量这些在后台项目页里配，与上传方式无关。

</details>

- 页面完整打开、「③ 接口自检」能跑、拿一个真实分享能列出文件列表。
- 重点多验一步：点一次需要后端的功能（比如接口自检），确认 `functions` 文件夹确实传上去了——只传了 `index.html` 时页面也能开，但所有解析功能都会坏。

****
- **页面能开、所有解析都报错**：十有八九是 `functions` 文件夹没传上去或没放在最外层。重新上传时把内容全选再传一遍。
- **上传时文件数对不上**：解压时被杀毒软件拦了某个 `.js` 文件，先关拦截或换解压工具，重新解压再传。
- **改了半天线上没变化**：这条路没有自动部署——你改的是本地文件，必须重新打包重新上传，线上才会变。

## 部署后必做配置

方法任选后，这几件做完才算齐活（第 1、2 件必做，第 3 件可选，第 4 件是验收）：

1. **建 KV 并绑定（保险箱/扫码绑定要用）**：CF 控制台 → **存储和数据库 → KV** → **创建命名空间**，名字随意（如 `ym-pan-kv`）；回到 Pages 项目 → **设置 → 绑定 → 添加 → KV 命名空间**，变量名**必须填 `PAN_KV`**，选刚建的命名空间，保存后重新部署一次生效。
2. **设巡检口令 PATROL_KEY**：Pages 项目 → **设置 → 环境变量** → 生产环境添加 `PATROL_KEY`，值自己想一串足够长的随机字符（勾选加密）。它用来：开保险箱设置窗口、调用巡检接口、重绑扫码凭证。**只存这里，不要写进代码或仓库。**（这把钥匙的保管方法与丢失处理，见「新手先看这里」钥匙节第 ③ 把。）

![环境变量与绑定](https://gcore.jsdelivr.net/gh/YiMing918/ym-pan@main/docs/cf-pan-env.png)
*填好的样子（真实截图）：① 变量和密钥里有 PATROL_KEY，值只显示「已加密」；② 同页绑定里有 PAN_KV。*
3. **（可选）绑自定义域**：Pages 项目 → **自定义域** → 添加你的域名（域名 DNS 需在 Cloudflare 托管），等 SSL 签发完成即可用自己域名访问。
4. **验收**：打开站点 → 点「③ 接口自检」全通 → 拿一个真实分享解析出直链 → 换个没登录过的浏览器打开站，确认保险箱能设口令。都过，部署完成。

## 认领站长：第一次打开先设口令

部署完的站有个「站长」位置：**谁先在站内设下保险箱口令，谁就是这个站的站长**。站长能用保险箱（把各家凭证存云端、换设备免填）、能绑巡检凭证。所以部署完**别先把链接发给别人**，先自己把这一节走完，把站长位置占住。

**第一次打开站点，你会看到什么**：页面和平时一样往下拉到「② 我的凭证 → 站长保险箱」卡，它会显示类似「还没设口令」的提示，并有一个设口令的输入框（能不能直接设，取决于你部署时配没配巡检口令，分两种情况）：

**情况 A：你没配 PATROL_KEY（巡检口令）** —— 可以直接设：
1. 在保险箱卡的口令框里，想一串**别和任何其他密码重复**的口令填进去，点「设置口令」。
2. **做到这里你应该看到**：页面显示一串**恢复码**并提醒只显示一次——**立刻把它抄进手机备忘录或密码管理器**（恢复码是什么、丢了怎么办，见「钥匙」节第 ⑤ 把）。
3. 设完刷新页面，保险箱卡变成「已设置口令/解锁」状态。**你就是站长了。**

**情况 B：你配了 PATROL_KEY** —— 设置窗口平时是**关着的**（这是防陌生人抢设的门，故意这样），保险箱卡会提示「设置窗口平时是关的（防陌生人抢设）」。你要先用巡检口令开一个 30 分钟的窗口：
1. 在**电脑浏览器**里打开你的站点，按 **F12** 打开开发者工具，点 **Console（控制台）**标签。
2. 把下面这段粘贴进去，把里面的字换成你自己的巡检口令，按回车：

```js
fetch('/api/owner', { method: 'POST', headers: { 'Content-Type': 'application/json', 'x-patrol-key': '把这里换成你的巡检口令' }, body: JSON.stringify({ action: 'open-setup' }) }).then(r => r.json()).then(console.log)
```

3. **做到这里你应该看到**：控制台打印出带 `ok: true` 的结果。回到页面刷新，保险箱卡的提示会变成「设置窗口已开启（30 分钟内有效）」。
4. 在 30 分钟内按情况 A 的第 1、2 步设好口令并抄存恢复码。窗口过期了没设完，就再执行一次第 2 步重新开窗，不影响任何数据。

设完口令之后：把各家凭证填进「② 我的凭证」的表格点「保存凭证」，**已解锁状态下保存会自动同步进保险箱**（存进你自己 CF 的 KV）；以后换手机、换浏览器，打开站点输一次口令解锁，解析就自动带凭证，不用重填。保险箱卡上会明文列出已存了哪几家（只列名字，凭证原文永不回显到页面）。

**千万注意**：站长口令只在**你自己的站**上设，别把口令告诉任何人、别让「帮你部署的人」替你设——这个站的设计就是口令不经任何人手（对方也看不到，服务器只存哈希）。万一忘了，恢复路径在「钥匙」节第 ④⑤ 把里写全了。

## 自动运维体系

- **一条坏了自动换另一条**：123 双接口路线、蓝奏多域名、夸克/UC 双网关形态——单点口径变化不至于全盘不可用；解析结果旁标注实际走通的路线。
- **凭证自动更新**：夸克/UC 的 `__puus` 每次响应轮换，本站自动回写本地凭证；保险箱里存的也会跟着更新。
- **口径跟随维护中的上游**：各家接口口径对照仍在活跃维护的开源项目（见下方来源总表）。哪家改版，对照上游新口径修对应适配器即可，其他家不受影响。
- **仓库看门狗（每日）**：`.github/workflows/watchdog.yml` 每天在 GitHub Actions 上巡检线上站点与全部接口，做两层检查（结构探针、真样本拉字节的可用性探针）；第三层夸克真解析巡检由部署者在仓库之外另行安排（调用巡检接口，见自动运维体系下条）；蓝奏镜像失效、123 路线主备这类机械故障会自己改 `parse.js` 顶部 CONFIG 区并触发重新部署，其余异常自动开 Issue 留痕。全程跑在部署者自己的 GitHub 账号上，不依赖任何外部服务；每月有心跳提交，防 GitHub 因仓库长期无活动停用定时任务。
- **夸克真巡检**：部署者扫码绑定后（见使用方法第七步），巡检接口 `/api/patrol`（PATROL_KEY 保护）可定期对固定测试分享做**真实解析 + 直链拉字节**验证——这是唯一带真凭证的端到端检查，比探活可靠得多。
- **维修交接**见 [MAINTENANCE.md](MAINTENANCE.md)：给站长的白话说明、各家口径速查表、故障签名对照、保险箱终极重置步骤与接手 SOP。

## 探活、保活与自动任务

### 探活：怎么知道自己的站还活着

「探活」就是**定时替你打开一下站点，确认它还能正常应答**，坏了第一时间能发现。本站一共有三层探活，从近到远：

**第一层：站内「接口自检」（手动，随用随测）**
打开站点 → 「③ 接口自检」→ 点「开始自检」，本站服务器会当场去试 11 家网盘官网接口通不通。某家解析坏了先点它：接口通而解析失败 = 多半是那家改了口径；接口不通 = 对方维护或临时封 IP，等一等。这层测的是「各家网盘」，不是测你的站本身。

**第二层：看门狗每日巡检（自动，见下方自动任务表）**
仓库里的看门狗机器人每天自动巡检线上站点 + 全部接口，修不了的问题会在仓库 **Issues**（问题帖）里开一张带 `watchdog` 标签的报告。**新手须知：看到这种机器人开的 Issue 别慌——那是自检报告，不是你的站被人攻击了**，照报告里写的内容处理（或等它自愈/等更新后）关掉即可。

**第三层：ym-dash 外部探活（自动，每 30 分钟）**
作者另有一套站点健康看板 **ym-dash** 在盯着本站：它每 30 分钟从外部请求一次 https://pan.1m.us.ci ，看板上绿灯/红灯 + 响应时间一目了然。你部署自己的站也可以这样盯：
- 若你也部署了 ym-dash（同一作者的测活看板项目）：打开 ym-dash → 登录 → 在站点管理里点**添加站点** → 名称填 `ym-pan`（随便起）、地址填**你自己的站点地址**（如 `https://ym-pan.pages.dev` 或你绑的自定义域）→ 保存。**做到这里你应该看到**：看板列表里出现你刚加的站，等一轮（最迟 30 分钟）或手动点一次检测，状态变绿就是探活在正常工作了。
- 没有 ym-dash 也行：任何「网站可用性监测」服务（如 UptimeRobot，免费）新建一个 HTTP 监测、填你的站点地址，效果一样。

### 保活：这个站需不需要「保活」

**结论：基本不用，这个站没有会睡着的东西。**
- CF 的 Pages / Functions / KV **没有休眠机制**：没人访问也不会被关、不会变慢，不需要定期去打开它「叫醒」。
- 唯一有「长期不用会被停」风险的是 **GitHub 的定时任务**：GitHub 规定仓库 60 天没有任何活动，会停用里面的定时工作流（看门狗就靠定时触发）。本仓库已内置对策——看门狗每月会留一个心跳提交，让仓库保持「有活动」状态，定时任务不会被停。**前提是你 Fork 后去 Actions 页把工作流启用过一次**（没启用过的心跳也不会跑）；万一发现看门狗几个月没动静，去仓库 Actions 页看一眼是不是被停用了，点启用即可。
- 需要**你人工偶尔盯**的就三件：①**域名续费**——绑了自定义域名的话，别让域名过期（过期了站就打不开了，这和保活无关、是域名本身的事）；②**KV 里的凭证会过期**——保险箱里存的各家凭证、巡检绑的夸克 Cookie，过期后对应功能会报错，重新在站内填一次/重新扫码绑定即可（凭证过期是常态，不是故障）；③**两把钥匙别丢**——巡检口令和站长口令/恢复码，保管方法见「钥匙」节。

### 自动更新与自动任务：一共哪些机器人在自动干活

| 自动任务 | 干什么 | 谁触发 | 频率 | 在哪看状态 | 怎么手动触发 | 失败了怎么办 |
|---|---|---|---|---|---|---|
| **deploy 部署** | 先跑冒烟测试自检，过了才把新代码部署到 CF Pages | 你推送代码到 `main` 分支时（仅方法二） | 每次推送 | GitHub 仓库 → **Actions** → deploy | Actions 页选 deploy → **Run workflow** | 冒烟红灯=不部署、线上保持旧版，先看红步日志；部署步红灯多半是令牌问题，回「钥匙」节第 ① 把检查 |
| **watchdog 看门狗巡检** | 巡检线上站 + 全部接口；蓝奏镜像、123 路线这类机械故障自己改配置并触发重新部署；修不了的开 Issue 留痕 | 仓库定时（schedule） | 每天一次（UTC 00:23，约北京时间 08:23） | 仓库 **Actions** → watchdog；异常结论看 **Issues** 里 `watchdog` 标签的帖 | Actions 页选 watchdog → **Run workflow** | 它自己失败会在 Actions 里标红、或把问题开成 Issue；你看 Issue 内容处理，处理完关帖即可 |

| **凭证自动回写** | 夸克/UC 的 Cookie 每次响应轮换新值，自动更新你本地（及保险箱里）的凭证 | 每次解析请求 | 实时 | 页面凭证框旁的状态 | 不用手动 | 某家凭证彻底过期时回写也救不回来，重新扫码/重新填一次即可 |
| **ym-dash 探活** | 从外部请求你的站点确认还活着 | ym-dash 的探活程序（定时任务） | 每 30 分钟 | ym-dash 看板 | 在 ym-dash 里对站点点手动检测 | 看板标红先打开站点自查；站能开多半是网络抖动，等下一轮 |

**关于「自动更新」再说清一句**：方法一/二下，你 Fork 的仓库**不会自己变出新版本**——原仓库发新版后，你要去自己仓库页点 **Sync fork**（同步复刻）拉一次新代码，拉完会触发自动部署（方法二）或 CF 自动部署（方法一）；方法三要重新下载代码再部署；方法四要重新下部署包再上传。这一步偷不了懒，是 GitHub Fork 的规矩。

## Fork 部署与原站的区别（为什么一开始没有自动更新）

- **Fork 到的是「裸站」**：不带站长保险箱里的任何凭证、KV 数据与巡检 Cookie。访客本来就用自己的凭证，体验与原站一致；站长自己的凭证要自己在保险箱里存、巡检 Cookie 自己扫码绑。
- **Secrets 不复制（GitHub 规矩）**：部署令牌、账号 ID 不跟随 Fork。部署工作流没令牌时自动跳过；要同款自动部署，按「部署方法二」在自己仓库配 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。`PATROL_KEY` 是 Pages 项目的环境变量，同样要自己设。
- **Actions 默认关闭**：看门狗（每日巡检）与部署工作流要去 Actions 页手动启用一次；启用后与原站同款。仓库 60 天无活动 GitHub 会停用定时工作流，仓库内置心跳保活，但前提是先启用。
- **不跟随的只有一层**：原站在仓库之外还有作者自己的站外每日真凭证巡检（口令与测试分享在作者手里），Fork 拿不到；仓库看门狗的探针层完整跟随，日常够用。巡检接口在代码里，想自建巡检自己设口令、绑凭证即可。
- **新版不自动流入**：原仓库更新后，在 Fork 页点 **Sync fork** 手动同步。

## 已知边界

- 直链都有时效（几十分钟到数小时不等，百度约 8 小时），过期重新解析即可。
- 百度风控最重：社区口径单个账号日解析下载约 200–300GB 会触发限流（错误 9013），长期超量可能封号 5–7 天——这也是本站坚持「只用自己凭证、不搞公共池」的原因。
- 夸克/UC 大文件必须先转存进你自己的盘（占空间），小文件可直取。
- 迅雷每类请求都要验证码令牌，低风险时接口直发、风控时可能要求人工验证，这是迅雷这家的固有难点。
- Cloudflare 免费额度：Functions 每天 10 万次请求、单请求 50 次子请求，个人自用绰绰有余。
- 蓝奏 2026 年起部分页面带 JS 人机挑战（`acw_sc__v2`），命中时纯接口过不去，会如实报错。
- B站视频从 Cloudflare 服务器出口常被其风控拦截（412），是出口信誉问题、不是代码问题；适配器保留，出口环境变化时探针会自动发现恢复。
- 小红书只认新鲜分享：网上流传的旧分享 token 多已过期，请在 App 里重新复制最新链接。

## 常见问题

**Q：为什么不直接在站里下载？**
A：直链交付给专业下载器（多线程、断点续传）体验更好；且中转流量既违反 CF 条款又烧额度。本站的活就是「问出地址」，下载交给 1DM+/ADM/aria2。

**Q：凭证安全吗？**
A：访客凭证只存在你浏览器的 localStorage（浏览器本地存储）里，随每次解析请求发给本站函数、函数用完即弃，不写任何数据库。站长保险箱的凭证存在站长自己 Cloudflare 账号的 KV 里，只对带正确口令的请求下发服务端调用，口令只存哈希。本站代码开源可查。给别人部署的站点请让访客各填各的。

**Q：解析速度/限速由什么决定？**
A：你的账号等级。SVIP/会员直链就是快，普通账号该限速还是限速——本站只负责拿到「你账号本该有的」那条链。

**Q：某家突然全挂？**
A：先跑「接口自检」：接口不通是该家在维护/封 IP 段，等一等；接口通但解析失败是口径改版，等本站按上游新口径更新适配器（或提 Issue（问题帖）附报错原文）。

**Q：我 Fork 了，为什么保险箱/扫码绑定不能用？**
A：多半是没做「部署后必做配置」：KV 没绑 `PAN_KV`、或没设 `PATROL_KEY`。照那一节补齐并重新部署一次即可。

**Q：部署一定要用 GitHub 吗？**
A：不用。方法四可以直接上传文件包；只是自动更新与看门狗依赖 GitHub，自用图省事可选方法一/二。

## 隐私

- 本站不设任何统计；访客凭证不落盘、不上传第三方（保险箱凭证只存部署者自己的 CF KV，见上）。
- 解析请求只会发往对应网盘/平台的官方域名。
- 部署者若配了环境变量凭证，等于自愿把该账号开放给站点访客解析，请慎重。

## 📦 部署包 · 优缺点 · 已知问题（速览）

### 部署方法（两种）

- **推荐：连 GitHub 自动部署。** 用上文方法一或方法二：Pages 连接仓库、或用仓库自带的 Actions 流程部署，再按「部署后必做配置」把 KV 等绑定补齐；以后推送代码自动更新。
- **手机备用：Release 部署包。** 在本仓库 Release 页下载最新部署包 zip，手机打开 Cloudflare 控制台 → Pages →「上传资产」新建项目上传，再补上同样的绑定和设置即可。适合救急或迁移到另一个账号。
- 两种方法都只是换程序：你填过的各家凭证存在自己账号的存储里，重新部署不会丢，不用一家家重填。

### 优点

- 定位专注：只做一件事——把网盘分享变成能直接下载的直链，不绑下载器、不搞会员。
- 多家网盘聚合在一个页面，解析前先填一次凭证，之后每家只管粘贴分享链接。
- 带接口自检：某家解析坏了能先自查是哪家的问题，不用瞎猜。
- 顺带做短视频去水印解析，免登录，日常小需求一个站搞定。

### 缺点 / 要花钱的地方

- 本身 0 元，跑在 Cloudflare 免费额度上；花钱的只有自备域名（可选）。
- 解析你自己的网盘文件，需要先填对应网盘的登录凭证（每家一次）——这是各家网盘的规则决定的，绕不过去；没有账号的网盘只能解析公开分享。

### 和同类有什么不同

- 市面上的解析站多是别人运营的：要么收费、要么广告多、你的凭证还要交给陌生服务器。这个是自托管版，凭证只进你自己账号的存储，解析也在你自己的部署里完成。
- 把「接口自检」做成了正式功能，源坏没坏一眼可见，这是多数解析站没有的。

### 已知问题 / 注意事项

- 解析成功率跟着各家网盘官方接口走：对方改接口、加验证时，对应一家会暂时失效，等修复更新即可。
- 个别网盘对解析频率有限制，短时间大量解析可能被临时拒绝，歇一会儿再试。
- 直链通常有时效，拿到后尽快下载；过期重新解析一次即可。
