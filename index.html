② 我的凭证 只存本机浏览器

凭证只保存在你这台设备的浏览器里，每次解析随请求发给本站函数调用官方接口，用完不落盘、不进服务器存储。哪家填哪家，不填的盘解析时会提示你。失效时重新粘一次即可；夸克/UC 的 Cookie 轮换会自动回写更新。
凭证从哪拿？（点开看每家的方法）
百度 BDUSS：电脑浏览器登录 pan.baidu.com → F12 → 应用/Application → Cookie → 找 BDUSS 复制。 阿里 Authorization：登录 alipan.com → F12 → 网络/Network → 随便点一个 api 请求 → 请求头里的 Authorization（Bearer 开头那串）。 夸克/UC Cookie：登录 pan.quark.cn / drive.uc.cn → F12 → 网络 → 任一请求 → 请求头 Cookie 整段复制。夸克认准 __puus 在里面。 123 Authorization：登录 123pan.com → F12 → 网络 → 请求头 Authorization。 天翼 Cookie：登录 cloud.189.cn → F12 → Cookie 整段。 移动 Authorization / 小飞机 token / 迅雷 Authorization：各自网页版登录后在网络请求头里找 Authorization。

③ 接口自检

检查各家官网接口从本站服务器能不能通（不查你的凭证）。某家解析坏了先点这里看一眼：接口还通多半是口径变了，回来反馈即可修。

本站怎么运作

  1. 只产直链：本站函数替你向各网盘官方接口问出真实下载地址，文件流量走你和网盘之间，不经过本站——所以不吃 Cloudflare 免费额度，也符合它的使用条款。
  2. 只用你自己的凭证：没有公共账号池（那种池子烧号、连坐封 IP、三天两头全灭）。速度和额度取决于你自己账号是不是会员。
  3. 多路线互备：123 有双接口路线、蓝奏有多个官方域名同码互备、夸克/UC 双网关——一条路线挂了会自动换另一条，解析结果旁会标明走了哪条。
  4. 部分直链要带请求头：百度要带 UA + 你的 BDUSS，夸克/UC 要带 Cookie，阿里要带 Referer。结果区会给出「链接+请求头」和现成的 aria2 命令，粘进下载器即可；1DM+ 在新建任务里能填请求头。
  5. 实验支持的盘：移动、天翼、小飞机、123、迅雷接口变动频繁，已按在维护的开源项目口径实现，但可能需要按报错迭代。光鸭官方分享接口未公开，筹备中，不上假接口。
  6. 已知边界：超大文件在夸克/UC 会先转存进你自己网盘再取链（会占你空间，可事后删）；百度风控最重，日解析量过大（社区口径约 200–300GB）会当日限流。
